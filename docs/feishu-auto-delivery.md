# 会议纪要自动交付

这是按用户明确偏好发布新纪要，不是会议/笔记同步。默认关闭，不回溯历史数据，不执行 ASR 或 LLM，不传原音视频。

## 设置与授权

桌面“插件 → 飞书”选择文档位置、本人/群/联系人，再启用“自动交付新纪要”。保存前确认位置、通知对象及阅读授权；取消保留草稿。只有当前桌面明确保存的授权会登记设备策略。其他设备共享飞书连接不等于在本设备开启自动上传正文。

自动交付确认同时说明启用飞书插件。普通安装或启用插件不会开启自动交付；停用或卸载插件先关闭当前设备尚未提交的自动任务，关闭未确认时保留插件状态并提示重试。

新选择联系人仍需要当前连接、应用、租户绑定的短时搜索凭据；保存后转换为服务端绑定的预设，不要求每隔15分钟重新搜索。保留旧联系人必须匹配同一已验证连接的现有名单，不能由客户端伪造姓名或添加任意ID。更换接收人、位置、连接或关闭功能会使旧策略失效；排队不会偷偷改发到新接收人。

## 生命周期

1. 仅桌面发起、拥有成功完成任务证据、首次保存为完成状态的新个人会议纪要可入队。保存正文与待交任务在同一数据库事务中提交；SQLite在insert savepoint之前明确开始外层事务。
2. 待交任务冻结正文、当前账号、策略ID及集成服务地址，不上传原件。首次保存资格与首次真实完成单独记录，不能通过修改status往返将旧稿变成新稿。新建未完成对象只保留创建当时的策略资格；启用前对象、旧策略或已完成对象不补交。永久删除后重新保存同一确定性ID仍可保存，但不重复自动授权。
3. 桌面进程运行时以一次性CAS领取待交任务，将正文交给原配置的集成服务。对外请求只携带在请求内存中的有效账号凭据，不保存新令牌，不跨Origin回退。
4. 集成服务确认接收后，持久后台调度器独立完成原生文档创建、正文转换/写入、阅读权限及逐对象通知。桌面关闭不终止已接收任务；尚未提交的设备任务需要应用运行。
5. 失败不撤销已保存纪要或已有文档、已成功通知。提供商写入结果未知时沿用原创建/正文/ACL/消息检查点，不能自动重放。启用新版后台调度器不会扫描历史手动任务或旧自动标记。

## 失败与恢复

- 设备未确认收到提交响应：保留原operation，在详情点击“核验交付结果”只查询原回执。404不等于服务没有接收，不能换operation重新提交。
- 原始设备提交结果未知时，其他手动发布入口也受保护，不能绕过未知回执再发。服务已接收不代表副作用已完成；新手动operation还必须核验原服务job确已完成，运行中、失败待处理或未知结果只能处理原任务。
- 确定提交前失败或服务明确拒绝：纪要保留，可在核对连接与设置后明确手动发布。不会无限自动重试。
- 服务已接收、部分通知失败：沿用原文档和原对象重试；成功对象不重发。权限/消息结果未知先核验，不能当作普通失败重试。
- 关闭开关会取消尚未领取的设备任务；进行中的请求不能撤回，但集成服务在后续写入前重验策略，不改投新对象。已送达文档和通知不会被删除。

## 实现与接口

- `feishu_auto_outbox.py`：设备策略与保存事务入队；`feishu_auto_runtime.py`：有界单线程调度和原operation只读恢复；`feishu_auto_policy.py`：服务端持久授权与联系人预设。
- `feishu_device_policies`、`feishu_meeting_saves` 与 `feishu_auto_outbox` 分别是设备授权、首次保存资格和冻结待交正文，不是workspace；统一在`init_db`注册，云端沿用现有RLS保护。
- `PUT /api/feishu/preferences` 增加预设contacts与明确自动交付授权；`GET /status`通过 `automatic_delivery_protocol=1`、策略及实际后台能力协商，旧服务不能由前端强行启用。
- `POST /api/feishu/automatic-deliveries` 仅接收operation、策略、来源键和正文，从服务端策略取接收人及位置。普通手动 `/deliveries` 的短时选择与当次确认限制保持不变。
- 设备 `GET /api/feishu/automatic-deliveries/local/{note_id}` 和 `POST /{note_id}/check` 沿用当前账号鉴权，后者仅按原operation查询服务，无新交付副作用。
- 设备 `POST /api/feishu/automatic-deliveries/device-disable` 要求当前账号与 `expected_user_id` 一致，只关闭本设备策略，不删除账号授权或已接收的交付。
- 新桌面转发状态请求携带 `X-VINote-Automatic-Delivery: 1`。公网服务向未协商该版本的旧 Bearer 客户端隐藏自动能力，避免服务器升级使旧 App 误认为具备保存后自动发布能力；此请求头只协商显示能力，不参与鉴权。

## 更新范围

桌面自带 API 随客户端更新；现有公网飞书集成服务需要配套新增自动交付协议与后台执行器。只更新 VINote 的飞书集成部署，不更新 VILab-server，不新增模型服务或账号系统。代码在功能分支审查、测试并正常合入 dev 后，才能更新集成服务。部署与真实消息验收仍需单独记录，不能用离线测试代替。
