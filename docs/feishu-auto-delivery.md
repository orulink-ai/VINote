# 桌面飞书授权、纪要发送与对象热词

本页描述当前功能分支；真实文档、消息和安装包验收单独记录，离线检查不代表已经发送成功。

## 三块设置

1. **授权**：通过官方 CLI 扫码配置用户自己的应用，再完成用户权限授权。首次使用可能有两个官方确认步骤，无需手填密钥或配置公网回调。桌面直接访问飞书，业务请求明确使用用户身份，不回退机器人或香港集成服务。
2. **会议纪要发送设置**：选择文档位置和本人、联系人或群，明确确认后开启后续新纪要的自动交付。默认关闭，不回溯历史稿，不因编辑重发，不调用 ASR/LLM，不上传原音视频。
3. **对象热词**：把常用称呼绑定真实联系人或群，支持搜索、同名区分和删除。可见缓存不代表完整通讯录，别称不替代身份或阅读权限核验。

## 凭据和运行边界

`VINOTE_DESKTOP_RUNTIME=true` 且 `VINOTE_FEISHU_TRANSPORT=cli` 才启用。两个模型渠道使用相同飞书连接方式，VILab 地址不参与飞书授权或发布。账号的 CLI 配置目录位于 `DATA_DIR/feishu-cli/<账号哈希>/`，通过 `LARKSUITE_CLI_CONFIG_DIR` 选择，不切换全局默认 profile。

Windows 新写凭据由官方 CLI 的 DPAPI/HKCU keychain 管理。CLI 兼容历史明文引用，因此不能宣称任意已有配置均已加密；配置目录隔离也不等于 keychain 隔离。Windows keychain 按 App ID/用户 ID 索引，PersonalAgent 注册可能返回已有应用。普通业务调用还持有官方 CLI 默认工作区的同身份刷新锁，避免与该工作区同时刷新；Windows 使用相同字节范围的 LockFileEx，已通过互斥测试和真实只读请求。应用注册、登录属于独立授权操作，不声称覆盖任意第三方自定义工作区。

VINote 数据库保存加密的应用/用户绑定和权限证据，不复制 App Secret、access token 或 refresh token。CLI 负责刷新和 DPoP，写入前核对实际用户。断开撤销 VINote 绑定和未提交队列，不退出其他 CLI 应用、不删除飞书文档。

源码开发需官方 CLI 原生程序。构建只把可执行文件打入 `bin` 并记录版本/SHA256，绝不打包开发者配置或凭据。`VINOTE_LARK_CLI_PATH` 仅是打包程序路径。

## 保存、发布与恢复

保存成功的新个人会议纪要与冻结待交正文在同一事务提交。桌面领取本机 outbox，按固定的应用、用户、连接、正文、位置和接收人创建文档、写正文、核验阅读权限并通知；关闭应用后需要重新运行才能继续核验，没有公网后台代跑。

新联系人选择仍需短时搜索证据，明确保存后转成同连接的预设，无需每15分钟重新搜索。改变设置不会把原队列改投到新对象。关闭开关取消未提交项，已经进行的外部请求不能撤回，后续步骤重新检查授权。

VINote 的每个步骤只调用一次 CLI，超时或输出丢失保留原回执，不自动执行第二次命令。官方 CLI 1.0.60 的 SDK 自身仍含拨号失败重试和默认 HTTP 重定向，因此一次 CLI 调用不能夸大为网络层绝对只发一次。现有正文 client_token、消息 UUID 和持久回执共同降低重复风险；未知创建、正文、ACL 或消息结果须先核验。

## 本机接口

- `feishu_cli.py`：原生进程、账号配置目录、官方二维码和有界用户授权。
- `feishu_cli_service.py`：复用 Markdown、阅读权限与发布回执，通过用户身份 CLI 调用飞书。
- `feishu_auto_outbox.py` / `feishu_auto_runtime.py`：保存事务入队、本机调度、原 operation 核验。
- `POST /api/feishu/authorize/complete` 只完成当前桌面账号的指定内存流程，不接受密钥。
- `/api/feishu/object-hotwords` 的读取、绑定、删除与 `/refresh` 只处理当前桌面连接。
- `GET /api/feishu/automatic-deliveries/local/{note_id}` 与 `POST /{note_id}/check` 核验原交付；`POST /device-disable` 关闭当前设备策略。
- 不提供公网 `POST /api/feishu/automatic-deliveries`，不新增 VILab 或公网后台能力，不部署服务器。

已支持参会人候选和逐会议的显式确认：候选只帮助人工核对参会人与被提及者，不会根据正文人名、说话人编号或时间重叠自动新增接收人。开启“发给会议参会人”后，首次自动交付若缺少当前证据和飞书连接下的有效确认，会等待确认，尚不创建文档或发送通知；也可明确确认本次不通知参会人。确认后仅恢复原先等待确认且明确尚未发送的交付意图，仍使用原 operation、冻结正文和已同意策略重新核验，不创建新意图，不重放 unknown、已受理或失败的交付。确认不代替接收人的阅读权限核验，也不新增员工状态查询权限。

## 画面分镜与信息图的交付

新交付先冻结同账号已保存正文、原任务的可信sidecar/源帧和渲染器身份。在任何远端节点或文档创建前，本机完整渲染PNG、验证全部页面并冻结顺序/语义/字节清单；正文仍是原稿，不改成拼图说明。复用原生图片writer的创建、上传、绑定、正文及回读journal，全部图片与阅读权限核验后才通知。恢复只使用原冻结PNG，丢失或不符时停止，不能重画、降为文字或重放未知写入。

形式标签不能替代生成授权。现代版本的DB回执或保留sidecar仍存在时，删除磁盘标记/改标签不能降为legacy；summary-only与fresh meeting_version回执均需原来源授权，null/损坏标记也不能授权。普通历史intake accepted行本身不建立版本身份，旧operation/unknown仍先查询原回执。此适配不新增scope、API、服务端后台或VILab能力；实际飞书图形写入、阅读权限及通知验收另列，离线模拟通过不等于已外发。

历史无形式metadata的已保存个人root只在严格owner/成功meeting来源且无现代版本/派生证据时保留正文快照发布，不补造形式；损坏metadata不属于历史缺失。新知识库会议分组仍需完整可信形式，不能借此退为文字或分配猜测版本。
