# VINote 界面落地规范

依据：飞书交互方案（私有链接已省略） 与其中的桌面/App 原型。视觉参考 [assistant-ui Native](https://www.assistant-ui.com/native)，桌面沿用现有 shadcn 基础组件，手机使用 React Native；没有引入该网站的示例 SDK。

## 2026-10-11 信息架构升级

用户已确认飞书 v2 并要求全面升级旧分类。此处覆盖 v2 中仍保留的“资料 / 集成”主导航分组；页面能力、版本、同步和恢复约束继续适用。

- 桌面主导航：内容工作空间、本机录制、处理记录；底部设置与账号。
- App 底部导航：工作空间、本机录音、处理记录、我的。导航仅由 App 根组件拥有，详情、表单与工具流程页不再各自装配底栏。
- 笔记内管理项目、标签与归档，导入和新建从记录或笔记上下文进入。
- 设置 / 我的中的“连接与工具”管理飞书及 MCP；详情进入对话、导出发布和工具执行。删除独立助手页，旧桌面 /assistant 深链接转到工作空间。
- 旧动态入口迁至任务；旧笔记库映射至笔记；空间与成员留在设置内。历史深链接兼容，不恢复旧分类界面。
- 同一内容拥有稳定标识，生成版本与编辑修订位于详情内。原音保留在来源设备；同步内容、原音可用性与处理临时上传分别说明。

后端共享内容使用 `/api/workspace`，MCP 使用 `/api/mcp-connections`；请求由已有 Cookie 或已核验的云端 Bearer 鉴权。开发手机经 USB reverse 连接本机共享后端，不等于公网共享服务已部署。完整实机验收仍在进行中。

## 共同约束

### 区域职责（2026-10-11 修订）

框架与业务页面分别拥有自己的区域，不能同时渲染相同标题、说明或主操作。`MainLayout` 负责区域装配，`Sidebar` 负责全局导航与查找入口，`PageHeading` 负责唯一的页面标题和主操作。旧 `Header` 已删除，不重新添加重复工具栏。页面内的筛选、内容与预览由该页面拥有，不由全局框架猜测路由后重复注入。

| 区域 | 放置内容 | 边界与恢复 |
| --- | --- | --- |
| 导航面板 | 品牌、全局查找；内容、本机录制、处理记录；底部设置与账号 | 独立于内容画布；可收起；不重复页面采集操作 |
| 框架状态区 | 仅连接故障、必要的处理状态；窄屏导航开关 | 不显示第二份页面标题或搜索框；正常同步信息留在账号与数据设置 |
| 页面头部 | 唯一 h1、必要的一句说明、唯一主操作及少量次操作 | 同一动作不再出现在框架；窄屏改换行或菜单，不能横向溢出 |
| 列表区域 | 当前页面的搜索、类型/归档/项目筛选、结果数量、列表 | 筛选与列表同面板；空筛选提供清除；刷新失败保留缓存并说明 |
| 选择预览 | 选中标题、来源时间、标签、短摘要、打开详情 | 与列表隔离；选中态一致；完整阅读进入详情，避免嵌套长正文滚动 |
| 详情内容 | 版本、纪要、逐字稿、基于内容的对话 | 页面层次稳定；保存失败留在编辑状态并保留草稿；冲突不覆盖另一端 |
| 原媒体与播放 | 原件位置、时长、播放器与导出 | 来自本设备才显示可播放；外设备原件明确说明；播放器不挤占正文工具栏 |
| 设置导航与面板 | 账号、模型、存储同步、连接工具、外观等明确分区 | 选中分区只显示对应设置；连接状态/测试/重试在连接卡内 |
| 全局进行中状态 | 录制、尚未完成的处理、需处理错误 | 无工作时不占一行；成功归任务历史；App 不重复永久“已同步”横幅 |

App 按屏幕宽度重组上述职责：列表点按进入详情，四入口底栏只负责导航；页头放一个标题和上下文操作；录音操作卡、搜索筛选、记录内容有独立区域。后台或不可见页面停止装饰循环。主操作保留至少 44pt 触控范围，不能以压缩内容为理由削弱点击目标。

### 同类产品调研与采用范围

2026-10-11 阅读以下官方资料。下面是适用于 VINote 的设计决策，不表示照搬其全部界面或功能。

- [Notion 导航](https://www.notion.com/help/navigate-with-the-sidebar)：侧栏承载内容组织与全局去向，搜索有独立入口。VINote 采用导航/搜索/内容分工，保持四个稳定主入口，不引入其完整页面树。
- [Notta 详情区域说明](https://support.notta.ai/hc/en-us/articles/37437047511195-Records-detail-page-screen-layout-and-functions-Notta-Web)：明确区分转写、播放、分析和记录操作。VINote 采用正文/证据/播放器分工，将分享导出归入当前记录操作。
- [Notta 两端播放](https://support.notta.ai/hc/en-us/articles/37552994549531-Playback-recording-or-video)：记录底部播放器与转写定位关联。VINote 保持时间戳跳转和播放位置一致，并独立处理原件缺失。
- [Granola 纪要核对与再生成](https://docs.granola.ai/help-center/taking-notes/ai-enhanced-notes)：从摘要追溯转写来源，编辑与重新生成各有入口。VINote 采用证据核对、版本选择及新版本生成，保留已有版本。
- [Amicro 作者 Skill](https://github.com/Subhan-code/Amicro--Micro-transitions-/blob/main/.agents/skills/amicro-design-system/SKILL.md)：采用画布/面板层次、pill 状态、`[0.16,1,0.3,1]` 缓动。其组件展示站专用的图库、代码复制与注册发布流程不属于 VINote 业务。
- [Uiverse wave-menu](https://uiverse.io/JkHuger/sweet-starfish-100)：将分时缩放节奏用于真实处理中的 Loading；不伪装成输入音量。作者与 MIT 许可保存在两端第三方声明中。

### 实现验收

- 1280×820 桌面与已连接手机实机逐页检查；同一视口不出现重复标题、说明或主操作。
- 每个可交互控件检查默认、悬停/按压、焦点、禁用、忙碌、错误恢复。键盘能进入所有动作，列表可访问名称只包含标题与状态。
- Loading 根据真实请求显示；不能无限转圈无错误出口；重试复用原数据与幂等操作，结果未知时先读取状态。
- 列表/详情返回保留选择和筛选；不会因为页面动画卸载正在录制的媒体控制器。
- 长纪要不在卡片中完整渲染；动画仅作用 opacity/transform；减少动效时静态显示，后台暂停循环。
- 删除旧入口与组件前检索引用，保留仍有业务职责的媒体/表单原语；不以删除数据或断开服务实现“清理”。

- 浅灰画布、白色内容面板、近黑正文、灰色辅助文字、细边界；桌面主面板圆角18px，控件圆角8–12px，导航选中态使用独立底色与图标。主操作黑底，次操作描边，其余文字操作。状态颜色只表示完成/失败，不替代文字。
- 页面标题24px、中标题18–20px、正文14–15px、辅助11–13px；正文有明确行高。手机使用打包中文字体并保留系统缩放，桌面使用系统无衬线字体。
- 常用间距8/12/16/24px。标题、列表正文和表单标签使用稳定对齐线。按用户最新要求重做框架并引入 Amicro / Uiverse 微交互：页面与标题轻量进入、按钮按压、导航选中、列表卡片悬停、面板展开和真实忙碌 Loading。已保存长正文不逐字重播；减少动态效果时取消位移和循环动画；不可见时停止装饰动画。
- 图标使用线性样式。手机和桌面应用图标来自 App 的品牌源。图标按钮有可访问名称，禁用状态禁止重复提交。
- 原型中的示例公司、项目、账号、波形和成功状态不作为真实业务数据；只有有依据的信息才能显示。

| 导入/任务/设置 | 导入在记录及笔记上下文；任务集中处理进度与恢复；设置内管理模型、账号、外观、存储同步、连接与工具 | 导入从记录或笔记进入；任务入口可跨页访问；我的按相同能力分区 |

## 状态与恢复

| 环节 | 正常 | 失败与重试 |
| --- | --- | --- |
| 列表 | 骨架、内容、空记录、空筛选独立 | 读取失败显示重试；清除筛选可返回全部，不删除原数据 |
| 录音 | 准备、录制、暂停、保存；保存后选择生成/稍后 | 权限/设备或保存失败保留恢复入口；未保存原件不得当成成功 |
| 生成 | 完整转写与本机声音分析并行，随后总结/核对/保存 | 保留原媒体与成功检查点；重试失败阶段，不把旧纪要覆盖成半份结果 |
| 详情 | 已保存版本、编辑草稿、原声跳转 | 读取/播放/保存分别恢复；失败保持草稿或原件；删除需确认 |
| 对话 | 资料内回答、流式状态 | 空白/网络失败保留问题，允许重试；不伪造回答 |
| 飞书设置 | 未启用、未连接、授权中、已连接、已过期 | 未启用显示配置说明；网络错误可重新读取；群失败保留已选群；保存失败保留修改 |
| 飞书交付 | 读取已有任务、文档、本人/群通知分步呈现 | 未读到状态前不可提交；保留已创建文档，重试失败通知；不确定建文档结果先恢复引用 |

会议时间只能来自录音元数据；笔记保存时间必须注明。波形来自真实原媒体，最多96点并缓存；失败不阻断回听/导出。声音编号只在本次录音内有效，未知与重叠保留，不把分组数解释为人数。

## 清理与验收

已替换：旧 `NoteGrid`、完整 `LocalRecordingCard`（有效预览能力进入 `LocalRecordingPreview`）、无引用 `CloudAccountPanel`、`PlaceholderSettingsPanel`、`popover`，以及旧卡片浮起/装饰动画。不保留可切回旧设计的分支；仍被引用的基础表单、弹窗、媒体和处理组件继续使用。

需要同时检查 Tauri 原生窗口与手机实机，不能只以浏览器或组件测试作为两端验收。正常、空数据、失败/重试用例结合现有回归与实际可用服务核对。当前飞书企业应用和共享集成服务尚未配置，真实 OAuth/建文档/机器人通知不能宣称已验收；iOS 新原生模块需 macOS 构建验证。
