# 录音自适应分段调用（2026-10-16）

用户确认允许合理分段；不按模型名字写死识别秒数，不自动换模型。

## 产品约定

- 录制时仅保存音频，结束后转写与说话人分析按原流程工作，汇合后生成并保存纪要。
- 已配置模型的识别能力与本次服务调用策略分开。一次550不成为“模型不支持长录音”的依据。
- 模型目录说明“录音转写 · 按停顿自动分段”；缺策略提示服务需更新，授权、额度、停用分别说明。保留用户选择，不暗中选择别的模型。
- 部分转写结果不会显示整体完成。已保存区间按实际音频时长累计进度；临时识别与最终落盘分开。

## 服务合同

`/v1/models` ASR `capabilities.recordedAudio`：`protocol=1`、`supported=true`、`strategy=adaptive_pause`、`maxSessionAudioBytes`、`policySource=service_budget`。默认2MiB是有界服务工作预算，不声称是提供方模型硬上限；管理员可按实际部署配置 `recordedAudioMaxBytes`。接受640至64MiB的偶数字节整数。非法配置 `supported=false, reasonCode=invalid_input_policy`。

VILab既有流式协议、模型标识、权限和最终结果判定保持。网络传输包大小与独立识别区间大小是不同概念。

## 桌面调用

1. 将音频标准化为16kHz单声道PCM16；用同账号、同Origin查询所选模型策略，不提交音频做探测。
2. 在预算内用20ms RMS窗扫描，寻找最后三分之一区域内至少240ms的相对静音，选最近停顿中点；持续发言没有合格停顿时，选择该区域最小能量点。分析窗口/停顿资格是声学参数，不是模型分段时长。
3. 用整数采样点存储连续边界，每个采样点恰好提交一次，无间隙、无重叠。没有词级时间证据时不伪造；会话级时间仍标为估计。此版本没有依靠文本相似度删除重复发言。
4. 冻结分段方案并逐段调用原模型，只有严格final返回才保存该区间。不得把partial当成功。
5. 请求前保存inflight标记；final结果和清除标记原子写入。同来源/账号/Origin/模型有独占锁，避免重复并发收费。`asr_checkpoint_lock.py`使用操作系统进程锁，进程退出后释放所有权，保留锁文件避免POSIX inode竞态；历史recognition.lock不自动回收。明确确认未发送任何音频的握手故障可沿用既有有界重试；已发送后的不明状态不重放。
6. 完成区间可复用；未知区间保留原记录，需核验或显式新操作，不能通过普通重进页面自动重试。损坏缓存不自动清空。
7. 完整final缓存先验证身份、模型、来源和覆盖，再复用；无需先刷新云端token。未完成部分只有实际需要目录或音频请求时才获取凭据。
