## 核心原则

1. 原始音视频不可被预处理覆盖；已确认结果持久化并可恢复。
2. 不自动换模型，不重放未知请求，不因空文本重跑整场。
3. 空文本不证明静音，也不证明技术成功；终态、传输和覆盖证据需要分别表达。
4. 背景声过滤不能只依赖音量或说话人占比；轻声发言可能有效。
5. 总结结构由会议内容决定，不固定章节、数量、篇幅或强制行动项。
6. 正文只呈现会议内容；普通空片段不写进报告。重要技术缺失在任务状态提示，不伪装完整成功。

## VINote 范围

| 模块 | 修改与验收要求 |

| 播放 | 查明长视频只能播放开头的根因；验证实际时长、读取范围、拖动、末尾播放及重开，不先假定是单一容器问题。 |

| 转写编排 | 按模型能力与停顿自适应分段，冻结模型，确认片段覆盖；可靠空文本保留内部记录并继续。 |
| 并行任务 | 录制后转写、说话人分析及必要视频分析并行但限制资源；明确最终材料就绪条件。 |
| 视频证据 | 覆盖完整时间范围，结合内容变化/文本变化/场景采样和去重；支持静态图、持续编辑白板和演示变化，不能把固定截图间隔当全程理解。 |
| 材料关联 | 对齐有效发言、说话人、画面、时间及来源；区分可见事实、口头决定与不确定材料，处理证据冲突。 |
| 视觉能力 | 区分支持图片的模型与文本模型；文本模型只能使用已提取视觉证据，不得声称读取了未输入的图片。额外视觉模型或费用需明确配置。 |

| 恢复 | 区分媒体重新加载、继续未完成处理、重新总结、新版本生成；未知请求先查询，避免重复计费。 |

## VILab-server 范围

- 核对各 ASR 适配器的成功终态、空文本、显式无语音、传输中断、上游失败与未知结果契约。
- 保持错误码、请求标识、处理阶段和现有可验证覆盖信息，诊断不得泄露凭证或原始音频。
- 只有实际协议证据允许时才能表达“正常终态但无文字”；不得将所有 empty_result_unverified、超时或异常改成成功。
- 更新目录能力中真实存在的约束与适用范围，不按品牌硬编码分段时长，也不编造供应商未提供的能力。
- 不把 VINote 的会议素材筛选、纪要结构和页面逻辑搬进通用模型网关。
- 若现有服务已经满足契约，优先修复 VINote 消费方式，不为此强行改服务端协议。

## 验证与交付顺序

1. 读取真实实现、旧日志和既有结果，建立失败/空文本/恢复的离线反例；不调用付费 ASR。
2. 先修完成性与恢复，再修多模态材料与总结质量；页面与飞书互不冲突的工作可并行。
3. 用保留结果测试总结、保存重开及发布状态；不发送未经授权的新消息。
4. 代码与离线验证通过后，再安排最少必要的真实调用，记录实际安装包与源代码证据差异。
5. 验收长视频开头、中段、结尾播放与拖动；正常、失败、继续、返回均验证。
6. 审查、中文 commit/PR、CI、合并、部署、部署后核验；不以脚本补救等同产品验收。
