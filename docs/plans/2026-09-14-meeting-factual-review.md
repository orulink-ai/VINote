# 会议纪要事实复核与交付验收

## 修订原因

首轮模板调整后，真实纪要仍存在执行主体误写、发布渠道被误写成互斥选择、由资料缺失衍生出未决问题等缺陷。仅依赖一次生成和模板中的自检要求不满足会议纪要的内容要求。

## 本轮实现

- 会议草稿增加独立事实复核。单次模式将原始转写和草稿分别传入，核对主体、否定词、范围、建议与决定、明确行动及时间依据。
- 长会议先对每个分块的草稿对照对应原始转写复核，再合并；最终一致性复核基于已核对的分块稿。最终合并仍受分块信息保留率影响，不声称等价于无限上下文的逐字全文审校。
- 云端复核优先使用目录中可用的 `MEETING_REVIEW_MODEL`，默认 `gpt-6-astra`。缺少该模型时沿用当前模型；自定义/本地模式复用当前提供方。不修改全局模型选择。
- 模型复核增加真实调用与延迟。失败或空结果不静默退回未经复核的草稿；实际复核模型通过既有 Langfuse 生成记录追踪。
- 两类安装包均携带相同的公开复核模型偏好，并保持部署服务默认地址。录音与账号凭证不进入安装包或 Git。

## 验证

- 后端：131 项通过（10 项已有弃用警告）。覆盖原始证据传递、复核结果返回、空结果拒绝、分块先核对后合并、模型可用性与主模型不被改写。
- 打包配置：4 项通过，包括显式空值沿用主模型。
- 文档站构建通过。
- 已对真实逐字稿运行应用内“生成初稿 → 事实复核 → 保存 → 回读”链路；复核修正了主要执行主体与渠道关系问题。额外的完整音频复测结果记录在本机忽略目录。
- 原音频完整复测成功，约 1153 秒；自动得到两个主要声音、104 段有效文本。随后用同一轮新逐字稿执行更新后的初稿与事实复核，约 72 秒，实际复核模型为 `gpt-6-astra`；保存回读和媒体 206 通过。样本的主要执行主体、复用流程、发布渠道、推进顺序和会议时间通过人工核对；一项分工回应不清，纪要未将其写为确认指派。此验收不等于全部短句或说话人归属均准确。
- 部署服务实际认证检查返回 HTTP 401 `Invalid API key or user access token`；本地服务接受同一身份。该环境问题需要部署端处理，不能将本地通过等同于部署端或安装包云端验收通过。

私有报告和测试日志保留在 `data/`，不将参考纪要内容、个人转写或音频提交到仓库。提交与推送以用户要求的验收条件为准，候选包不能标为已通过部署端云端验收。
