# 会议录制交互与实时逐字稿

## 当前发现（2026-09-18）

- 悬浮控制器窗口约 360×132，内部 AlertDialog 超出窗口边界，造成结束按钮难以点击。结束确认应由主窗口承载。
- 会议页限制为 1180px，大计时器、装饰波形、说明卡片占据主要区域；控制、内容、历史没有按阶段分开。
- “会议记录”和“生成会议纪要”已拆分为不同处理模式：前者只保存本地媒体，后者在录制时连接真实实时 ASR，并在停止后优先复用 final 逐字稿生成纪要。
- 当前仍保留整文件 HTTP STT 与完整录音说话人分析，作为实时服务失败、没有有效 final 逐字稿或用户稍后生成纪要时的可靠回退。
- 屏幕与麦克风已验证录制、保存和回放；系统音频完整链路仍需验证。缺失电脑音轨必须显式提示，不能冒充采集完整。

## 统一交互

1. 会前：先选择“会议记录”或“生成会议纪要”，再选择语音或视频、麦克风和保存空间。视频模式进入系统屏幕选择。模型配置通过设置进入，不占会前主界面。
2. 会中：会议记录模式专注录制状态、画面和控制，不启动实时 ASR；会议纪要模式自动启动真实实时 ASR，以逐字稿为主，屏幕预览可收起。底部固定暂停/继续和结束并保存，不提供会改变模式含义的独立转写开关。
3. 结束：主窗口内确认，继续录制/结束并保存两个清楚的操作。悬浮窗发送确认请求，不能在窄窗里弹出大对话框。确认前保持录制；保存中防止重复提交。
4. 会后：会议记录模式保存媒体后返回历史，可播放、预览、下载、复制、分享、删除或稍后生成纪要。会议纪要模式有有效 final 逐字稿时直接生成；没有 final 或实时服务失败时保留媒体，之后走完整文件转写。生成失败可重试且不丢录制和已有逐字稿。
5. 离开页面：采集和转写由主窗口的持久控制器持有；悬浮条提供计时、暂停、结束、返回，均操作同一会话。

采用原则：借鉴成熟交互，不复制产品视觉；所有动画、音量、文本和说话人状态必须来自真实运行状态。上游实时服务不可用时明确显示降级状态并继续本地录制。

## 内容布局

- 主体使用可用宽度，上限 1600px，侧栏可收起；调整布局而非整体放大组件。
- 标题 24–28px，正文 14–16px；常用操作点击区域至少 44px。内容块间距 24px，表单项 16px。
- 录制区采用 `minmax(0,1fr)` 的内容列与 280–360px 可收起预览列；窄窗口改为标签切换，不挤压两列。
- 录制状态必须反映实际状态。音量动画取真实音量，不用永久循环的装饰波形表示声音已采集。
- 逐字稿使用指定的 ElevenLabs Conversation 组合，沿用 shadcn 控件。新段落轻量出现；用户向上阅读时暂停跟随，显示回到最新。

## 实时逐字稿数据与行为

一行包含 `segmentId / revision / kind / speakerId / startMs / endMs / text / soundLabel / confidence / final`。

展示示例：

> 说话人 1 · 00:12
> 我们先确认今天的议题。
>
> 说话人 2 · 00:16
> 我补充一下昨天的结果。

- 临时文本在同一段中更新，稳定文本追加；不每次回调都插入新消息。
- 说话人编号必须由同一会话中的稳定识别结果产生，不能按声道、消息顺序或独立分片的编号伪造身份。麦克风与电脑声音都可能包含多人。
- 未确定身份显示“未识别说话人”，重叠发言保留不确定状态；允许重命名，后续同一说话人同步更新。
- `kind=sound` 单独显示笑声、掌声、音乐、键盘声、门铃等有意义事件。静音、普通呼吸和持续底噪不产生消息；同类事件在短时间内合并，避免刷屏。
- 静音不结束录制；转写失败或网络断开不影响本地录制，界面显示中断状态并提供恢复。
- 暂停、继续与转写时间轴一致。重连使用序号去重；结束先保存媒体，再完成剩余转写，不用识别服务阻塞保存。

## 实时转写状态机

- `disconnected`：未启用或当前服务没有实时能力。
- `connecting`：创建会话和协商音频格式，录制器不等待该状态完成。
- `listening`：接收 partial、final、speaker 与 sound 事件。
- `reconnecting`：网络短暂中断，保留本地录制并按序号恢复，界面提示正在恢复。
- `unavailable`：服务拒绝、模型不支持或持续重连失败；本地录制继续，会后使用完整录音转写。
- `finalizing`：停止录制后保存媒体，并等待已发送音频对应的最后确认段；超时也不能阻塞本地保存。

## 会中页面结构

- 宽窗口：逐字稿约占 70%，录制画面约占 30%；画面可收起，逐字稿获得剩余宽度。
- 窄窗口：使用“逐字稿 / 画面”标签切换，不把两列压成狭窄卡片。
- 顶部只保留会议名、录制状态、时长与实时服务状态。
- 底部固定暂停/继续、悬浮控制、结束录制；主要按钮点击区域至少 44px。
- partial 文本使用轻量淡入或内容更新动画，final 后停止闪动；连接、重连、暂停和声音事件均只根据真实状态动效。

## 后端接入边界

- 复用当前账号、用户模型选择和服务端凭证。前端不直接持有上游密钥。
- 已新增受认证的实时连接配置接口，实时会话复用当前用户个人令牌；服务端和上游共同检查用户身份、格式、消息大小及并发限制。
- 采集音频独立分流为单声道 PCM，录制器继续保存完整媒体；不要把 MediaRecorder 的任意 WebM 分片当成可独立解码的文件。
- 会议纪要模式连接部署的实时 ASR，转发真实 partial/final、speaker 与背景声音消息；能力不可用时明确降级，不能用假的实时消息填充界面。
- 若服务不返回说话人，需要会话级在线说话人处理和跨片段映射；当前整文件 diarization 只能用于会后校正。
- final 逐字稿、实时状态和诊断随本地录制一起持久化并关联录制 ID；停止后纪要优先复用 final 逐字稿，没有可用 final 时才回退完整文件识别。

## 验收

- 1040×680、1280×820 与系统缩放下确认按钮完整可见；主窗口和悬浮条结束行为一致。
- 实际屏幕、麦克风、电脑音频分别验证；静音、暂停、恢复、停止保存及重开回放通过。
- 两位真实说话人交替发言，核对文字、身份稳定性和录制偏移；服务故障不丢本地媒体。
- 当前已实现：两种会议模式、主窗口统一结束确认、显式系统音频降级、真实实时连接契约、PCM 音频分流、ElevenLabs Conversation 逐字稿、partial/final 原位更新、final 逐字稿本地持久化、实时失败时继续本地录制，以及停止后直接复用 final 逐字稿生成纪要。
- 后续增强：更稳定的在线说话人跨段映射、更完整的背景声音事件、网络断线续传和会后整文件结果对实时逐字稿的校正。这些增强不阻塞当前录制、保存和生成纪要闭环。
