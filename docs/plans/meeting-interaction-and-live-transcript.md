# 会议录制与会后处理（2026-09-21 替代旧实时逐字稿设计）

录制期间，两种模式均只采集媒体，不建立实时 ASR 连接，不发送转写音频，不展示临时识别和说话人。保留真实音量、时长、暂停/继续、结束及可选屏幕预览。

结束时先保存原始媒体和 IndexedDB 记录，转移 OPFS 文件所有权，再退出录制控制。会议记录模式不调用模型；会议纪要模式自动提交完整媒体，由独立的逐记录任务完成会后处理，不要求再次点击生成。

会后沿用本地 sherpa-onnx 说话人区分、内网 VILab 转写与总结，以及视频代表帧实际图像分析。按照时间区间对齐说话人，不由总结模型猜测身份。当前本地说话人分析和云端转写串行执行。

状态与恢复：原始媒体保留；失败展示阶段和原因；重试沿用任务、有效转写分段和画面证据；服务重启后将中断任务标为可重试。笔记及任务使用录制身份去重，后台处理不能修改另一条正在录制的采集状态。

转写进度来自完成分段覆盖的音频秒数；有实际结果后按处理速度估算剩余时间。短录音的整文件接口没有流式进度，等待时明确显示无法估算，不伪造百分比。

本地记录支持预览、下载文件、确认删除和生成/重试；生成完成后可查看服务端媒体、逐字稿、说话人别名和纪要。纪要沿用现有分享权限。独立原始媒体分享、系统文件剪贴板、独立逐字稿删除/分享仍未实现，不生成本机路径分享链接。

验证证据和限制见 [本次验收记录](2026-09-21-meeting-postprocessing.md)。旧实时 ASR、PCM 分流、实时健康分支与相应连接接口已删除。
