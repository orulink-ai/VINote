# PR #31 功能迁移与架构取舍

## 目标

PR #31 包含一批有价值的会议记录与证据回看能力，但它同时把 VINote 的下载、转写、
总结和截图链路整体迁入 VILab Server。这与当前产品边界不一致：

- VINote 继续拥有笔记生成业务、任务产物和本地/远程模型配置。
- VILab Server 只作为可选中转网关，负责把请求路由到外挂的 ASR、说话人识别和 LLM 服务。
- 未配置或暂时不可用的 VILab Server 不得阻断 VINote 本地链路。

因此不直接合并 PR #31，而是在最新 `dev` 上逐项迁移价值。

## 本次实现边界

### 1. 笔记转写证据

- 后端从笔记对应任务目录的 `transcript.json` 读取证据，不依赖上游运行 ID。
- 转写片段采用向后兼容字段：`text`、可选 `raw_text`、`cleaned_text`、
  `speaker_id` 和 `speaker_label`。
- 说话人别名保存在笔记 `structured_json` 中，并沿用个人/团队笔记访问控制。
- 前端提供双视图、原始/清洗切换、别名编辑、时间跳转、播放跟随和独立导出。

### 2. 媒体保真

- 任务目录记录 `source_media.json`，包含相对路径、媒体类型、大小和 SHA-256。
- 媒体读取只接受任务目录内部的常规文件，拒绝绝对路径、父级逃逸和符号链接。
- 笔记媒体接口优先返回清单声明的原始文件，再兼容旧任务的媒体发现逻辑。
- 浏览器录音上传保留 MediaRecorder 的原始 Blob；后端继续负责必要的 WAV 转换。

## 后续网关接口原则

后续 VILab 网关适配必须满足：

1. 配置是可选的，并与 VINote 现有 LLM / STT 配置并存。
2. VINote 只依赖稳定的能力契约，不依赖网关内部模型名称或部署方式。
3. 网关不可用时，本地链路仍可创建、转写、总结和浏览笔记。
4. 实时事件、错误和模型元数据先归一化为 VINote 自己的领域模型，再进入 UI。
5. 上游任务 ID 仅作为外部执行引用；VINote 的笔记、权限和任务产物仍由 VINote 管理。
